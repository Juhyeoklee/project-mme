## 여기부터 복사

`project-mme`라는 이직용 포트폴리오 사이드 프로젝트를 진행하고 있어. 기술 구조는 이전 세션에서 확정했고, **이번 세션의 목표는 아이디어를 디벨롭해서 화면 IA까지 도출하는 것**이야.

### 먼저 읽을 것

이 프로젝트에 첨부된 문서 **`claude/project-mme-architecture.md`** 를 `project_read`로 읽어줘. 확정된 기술 구조와 결정 근거가 전부 들어 있어. 로컬 폴더가 연결돼 있으면 `docs/ARCHITECTURE.md`에도 같은 내용이 있어.

특히 이 세 곳을 꼼꼼히 봐줘.

- **§17 검토했지만 채택하지 않은 것** — 이미 닫힌 논의야. 다시 열지 말고, 뒤집고 싶으면 그 근거를 먼저 반박해
- **§18 다음 세션 인계** — 이번 세션에서 풀어야 할 문제가 정리돼 있어
- **§8 WebView 정책 / §11 TCA 기준** — 화면을 분류할 때 쓸 판단 기준

### 제품 요약 (문서에 다 있지만 미리)

게임 스크린샷을 정리하고, 기억할 만한 순간을 기록으로 남기는 앱. 지금은 카카오톡 안의 도구로 하고 있어.

유저가 지금 하는 일은 이 세 단계고,

1. 스크린샷 폴더를 쭉 훑는다 → **지겹다**
2. 그날 그 순간 사진들을 눈으로 묶는다 → **귀찮다**
3. 무슨 일이었는지 글로 쓴다 → **이건 재밌다. 건드리면 안 된다**

**1~2를 없애고 3만 남기는 게 제품의 전부야.**

### 이번 세션에서 풀 핵심 난제

> **자동으로 묶어준 그룹을 유저가 어떻게 고치는가.**

"묶기"는 알고리즘 문제지만 **"묶은 걸 쪼개고 합치기"는 인터랙션 문제**고, 후자가 훨씬 어려워. 자동화가 틀렸을 때 고치는 비용이 크면 자동화 자체가 짐이 돼. 여기 설계가 제품 체감 품질을 결정해.

딸린 질문들:

- 그룹의 표현 단위 — 날짜? 세션? 둘 다? 계층 구조?
- 자동 그룹핑을 언제 돌리나 — 임포트 시점? 조회 시점? 백그라운드?
- 유저 수정을 어떻게 보존하나 — 재실행하면 수정이 날아가면 안 돼
- 그룹에서 기록으로 넘어가는 동선
- 기록 카드 내보내기 형태 (카톡·인스타 공유용)

### 반드시 지킬 제약

문서에서 확정된 것들이야. 넘으려면 먼저 나한테 근거를 대고 물어봐.

- **AI는 그룹핑에만 쓴다.** OCR, LLM 초안 생성, 베스트컷 추천은 이미 탈락시켰어
- **MVP는 "날짜별 정리"까지.** 그룹핑·기록은 2단계, 서버는 3단계
- **1~2단계에 서버가 없다.** 로컬만으로 동작해야 해
- **WebView는 "웹에 이미 존재해야 하는 화면"만** — 현재는 공유 기록 뷰어와 약관류뿐
- **스크린샷 전량은 서버에 올리지 않는다.** 유저가 기록으로 남긴 것만
- **범위 확장은 ADR을 쓰게 강제.** 기능 추가 아이디어가 나오면 "이건 MVP 밖"이라고 표시해줘

### 아직 안 정한 것 (이번에 정해도 좋고 미뤄도 좋아)

- 앱 이름
- 근접중복 임계값 미세조정
- 최소 지원 OS 하한
- 로컬 DB SwiftData 확정 여부

### 스파이크가 이미 끝났어 — §4는 측정값이야

실제 스크린샷 60장 / 12일치로 검증했고, 결과가 문서 **§4**에 들어 있어. **추측이 아니라 실측이니까 여기 어긋나는 설계는 틀린 설계야.** 특히 이 다섯 개가 IA를 직접 규정해.

- **HUD가 없다** — 게임 내 촬영 모드라 UI가 통째로 빠진 순수 장면이야
- **시간 30분 기준으로 세션이 잘 나뉜다** (60장 → 22세션). 임계값이 둔감해서 튜닝이 필요 없어
- **날짜별 정리로는 부족하다** — 12일 중 5일(42%)이 하루에 세션 2개 이상. 그래서 MVP가 "세션별"로 올라갔어
- **시각 유사도는 시간을 대체할 수 없다** (ARI 0.23~0.44). **시간이 1차 축, 시각이 2차 축**이야
- **신경망이 필요 없다** — pHash랑 HSV 히스토그램으로 충분해서 모델 배포 문제가 통째로 사라졌어

즉 A안/B안을 나눠 고민할 필요가 없어. **시간 기준 세션이 확정된 1차 축**이고, 시각 유사도는 그 위에 얹는 부가 기능이야.

### 실측이 만들어낸 구체적 하위 질문

이게 IA의 진짜 쟁점들이야.

- **1장 세션 6개를 어떻게 표현하나** (22세션 중 27%). 세션으로 보여주면 노이즈, 낱장으로 빼면 일관성이 깨져
- **12장 세션(7/26 18:05)처럼 큰 세션을 어떻게 보여주나.** 장수가 곧 중요도 신호인가?
- **근접중복 9쌍을 어떻게 접나.** 자동으로 접고 대표 1장만? 유저가 펼칠 수 있게?
- **종횡비가 혼재해** — 해상도 7종에 세로 사진(708×954)도 섞여 있어. 그리드 레이아웃에 처음부터 반영해야 해

스파이크 코드와 썸네일 리포트는 `spike/`에 있어. 재현 가능해.

### 작업 방식

내 성향이니까 참고해줘.

- **대화형으로 진행해.** 한 번에 완성본을 내놓지 말고, 한 덩어리씩 보여주고 내 반응을 받아
- **깊은 웹 리서치는 하지 마.** 필요하면 먼저 물어봐. 이건 UX·IA 설계 작업이고 최신 API 조사가 아니야
- **의견을 분명히 말해.** 선택지만 늘어놓지 말고 어느 쪽이 낫다고 생각하는지, 왜 그런지 근거를 들어서 말해줘. 반대 의견도 환영이야
- **범위를 경계해.** 나는 자꾸 기능을 덜어내는 쪽을 택했어. 계속 그 방향으로 밀어줘
- 이건 **사이드 프로젝트**야. 완성돼야 포트폴리오가 되니까 완주 가능성을 항상 계산에 넣어줘

### 최종 산출물

대화가 정리되면 **`화면 IA 문서`** 를 만들어줘. 담을 것은 이거야.

1. **기능 정의** — 아이디어 디벨롭 결과. MVP 안/밖을 명확히 구분
2. **화면 목록 (계층 트리)** — 전체 구조를 한눈에
3. **화면별 상세** — 각 화면마다:
   - 목적 (한 줄)
   - 진입점
   - 핵심 상태
   - 주요 액션
   - **플랫폼 차이** (iPhone / iPad / macOS / Web)
   - **네이티브 or WebView** (§8 기준 적용)
   - **TCA or `@Observable`** (§11 기준 적용)
4. **주요 플로우** — Mermaid 다이어그램으로. 최소 세 개:
   - 온보딩 (앨범 지정 → 첫 정리)
   - 정리 → 그룹 수정 → 기록 작성
   - 기록 게시 → 공유 링크
5. **미해결 질문** — 다음 단계로 넘길 것

문서는 **로컬 `docs/IA.md`에 쓰고, claude.ai 프로젝트에도 `project_write`로 올려줘.** 그래야 또 다른 세션에서 이어받을 수 있어.

### 시작

먼저 문서를 읽고, **핵심 난제(그룹 수정 인터랙션)에 대한 네 생각부터** 말해줘. 바로 IA로 뛰지 말고 거기서부터 대화를 시작하자.
