# 0001 — 모듈 경계와 의존성 규칙

> 상태: **확정** · 2026-08-02
> `repo/docs/adr/`의 첫 문서. 번호는 4자리 순번, 재사용하지 않는다. ADR은 고쳐 쓰지 않는다 — 뒤집을 땐 새 번호로 대체하고 여기엔 상태만 남긴다.

## 맥락

첫 마일스톤(M1)은 화면 셋 — 순간 목록 · 순간 상세 · 사진 전체화면, iOS·iPadOS. 구현 전에 모듈 경계와 의존성 규칙을 한 번만 정한다. 이 프로젝트는 경계를 말이 아니라 기계가 강제하게 만드는 것을 주 무기로 삼고, 경계가 취향이 아니라 문제 구조에서 나왔음을 보이려 한다(`WHY.md` §1).

이 제품의 구조적 사실은 셋이다.

- **ⓐ 원본은 읽기 전용이다.** 사용자의 스크린샷을 읽기만 한다는 것이 서비스 약속이다
- **ⓑ 순간(자동 분류의 결과)은 사용자가 편집하지 않는 파생물이다.** 따라서 M1에는 저장할 사용자 산출물이 없다 — 순간은 매번 재계산해도 제품이 성립한다
- **ⓒ 다른 언어 구현과 같은 결과를 내야 하는 로직이 정확히 하나 있다.** 분류다. 뒤 마일스톤에서 웹 자산 구현이 같은 사진을 같은 순간으로 묶어야 한다

## 결정

**1. 절단 기준** — 모듈은 *"무엇을 알아도 되는가"* 로 가르고, **구조적 사실이 기계 강제를 요구하는 곳에서만** 가른다. 계층(Domain/Data/Presentation)도 기능군도 기준이 아니다.

**2. M1 모듈과 간선** — 영역 셋, 패키지 둘.

```
        ┌──────────────────────────────────┐
        │ App — 화면 3 · 내비 · 디자인 토큰      │
        └───────┬──────────────┬───────────┘
                ▼              ▼
        ┌────────────┐   ┌──────────────┐
        │ PhotoSource │──▶│ MomentKernel │
        │ Photos 유일  │   │   import 0   │
        └────────────┘   └──────────────┘
```

- **`MomentKernel`** — 사진 메타값 배열 → 날짜·순간·장면 구조. 순수 함수, import 0
- **`PhotoSource`** — 사진 라이브러리를 아는 유일한 모듈. 메타값 읽기와 픽셀 로드. **공개 API에 쓰기 연산 없음**
- **`App`** — 화면 · 내비게이션 · 디자인 토큰 · 오케스트레이션. 토큰은 별도 모듈로 만들지 않는다
- 계약 타입(커널의 입출력)의 주인은 커널이고, 어댑터는 그 타입을 방언 없이 쓴다

이 목록과 이름은 **결정 시점의 스냅샷**이다. 이후의 진실은 `Package.swift`다.

**3. 물리 형태** — 앱 타깃 하나 + **로컬 SPM 패키지**. Xcode 타깃 분리와 Tuist는 탈락.

**4. 강제 수단** — 두 층이다. **패키지 간 화살표는 컴파일러가**(SPM 의존 선언 없이는 import가 컴파일되지 않는다), **컴파일러가 못 막는 셋은 직접 만든 최소 검증기가** 막는다: ① 커널의 플랫폼 프레임워크 import ② App의 사진 프레임워크 직접 import ③ 어댑터 내부의 쓰기 심볼 사용. 검증기의 범위는 이 셋과 정확히 일치한다 — 컴파일러가 공짜로 하는 일을 다시 만들면 그 순간 탈락이다. 위반의 빨간불은 **CI 잡 하나**의 실패이며, 같은 스크립트를 로컬에서 돌릴 수 있다. 구현은 다음 세션.

**5. 플랫폼 분기의 주소** — 층마다 사는 방식이 다르다. **커널: 분기 금지**(입출력에 플랫폼 정체가 등장하지 않는다) · **어댑터: if문이 아니라 구현체 교체**(macOS의 폴더 소스는 조건문이 아니라 같은 계약을 말하는 새 모듈) · **UI: 표현 분기가 사는 유일한 곳**(2-pane/push 등). 분기 기준(size class 등)은 구현에서 정한다 — 여기서 정하는 것은 주소뿐이다.

**6. 분류는 플랫폼 사진 프레임워크를 모른다.** 그리고 **커널 입력에 들어오는 모든 값은 계약이다** — 값을 만드는 과정이 플랫폼 프레임워크에 기대면, 그 과정까지 다른 언어 구현이 재현해야 할 계약의 일부가 된다. 그 비용을 물고 신호를 채택할지는 알고리즘 결정의 몫이되, 경계는 이 문장으로 지킨다.

## 근거

**1.** 3계층의 Domain/Data 분리는 *"저장 기술을 갈아끼울 수 있는가"* 에 대한 답이다. M1은 그 질문을 하지 않는다(ⓑ — 저장할 것이 없다). 이 제품이 실제로 묻는 것은 *"플랫폼 사진 API가 바뀌어도 분류 결과가 같은가"*(ⓒ)이고, 그 답은 계층이 아니라 순수성으로 갈린다. 기능군 절단은 M1에선 같은 그림으로 수렴하지만, 기준으로 선언하면 뒤 마일스톤에서 기능군마다 모듈을 늘리라는 압력이 되어 완주를 깎는다.

**2.** ⓒ가 커널을 가른다 — 다른 언어가 같은 입력을 받으려면 입력이 플레인 값이어야 하고, 분류가 플랫폼 객체를 입력으로 받으면 계약이 원리적으로 성립하지 않는다. ⓐ가 어댑터를 가른다 — 사진 프레임워크를 한 모듈에 가두고 공개 API에서 쓰기를 빼면, 나머지 코드에는 원본을 건드릴 경로가 컴파일 타임에 없다. 두 사실이 같은 선을 반대편에서 가리킨다. 토큰 모듈을 안 만드는 것은 절단 기준의 적용이다: 토큰 경계를 요구하는 구조적 사실이 없고, M1의 토큰 소비자는 화면 셋뿐이다. 승격은 두 번째 소비자가 생길 때.

**3.** 로컬 SPM 패키지는 화살표 방향을 컴파일러가 공짜로 강제하고, 경계의 진실이 사람이 읽는 선언적 텍스트(`Package.swift`)에 남는다. Xcode 타깃 분리는 그 진실이 `pbxproj`에 산다 — diff로 읽히지 않는 게이트 설정은 이 프로젝트의 목적과 자기모순이다. Tuist가 푸는 세 문제(pbxproj 머지 충돌 · 수십 개 타깃의 일관성 · 대규모 빌드 캐싱)는 이 프로젝트에 하나도 없다 — 혼자, 타깃 셋, 소규모. Bazel·Nx를 자른 논리(`WHY.md` §5)가 규모만 다를 뿐 같게 적용된다.

**4.** 시스템 프레임워크는 SPM 선언 없이도 어느 모듈에서나 import된다. 즉 위 ①②③은 컴파일러가 못 막는 실재하는 구멍이고, 목록이 비어 있지 않으므로 도구가 정당화된다. 기성 도구(SwiftLint custom rule)를 안 쓰는 이유: 어차피 규칙 본문은 직접 써야 하는데, regex 몇 줄을 위해 도구 의존성을 들이는 것은 배보다 배꼽이다.

**5.** 커널의 분기 금지는 ⓒ의 다른 표현이다 — 분류에 플랫폼 분기가 있으면 *"같은 사진이면 같은 결과"* 가 원리적으로 깨진다. 어댑터의 "구현체 교체" 규칙은 다음 마일스톤을 미리 설계하는 것이 아니라, macOS(폴더 소스)와 웹 자산 구현이 왔을 때 전면 재배치 없이 모듈 추가로 흡수되게 하는 규칙이다. 분기가 아래층으로 새는 냄새의 판별식: *"기기에 따라 커널 출력이 달라야 한다"* 는 요구가 나오면 그건 표현 분기가 데이터 형태로 새고 있는 것이다.

**6.** 결정 2의 귀결이지만 별도로 못 박는 이유: 커널이 순수해도 **입력값의 생산 과정**이 플랫폼 종속이면 계약이 커널 밖에서 깨진다. 이 구멍은 알고리즘 선택 시점에 열리므로, 그 시점에 읽을 문장으로 여기 남긴다.

## 결과와 대가

**얻는 것** — 원본 불변이 테스트가 아니라 구조로 보장된다. 분류 계약이 코드의 한 곳(커널의 입출력 타입)에 보인다. macOS·웹 자산은 재배치 없이 모듈 추가로 흡수된다. 경계가 상태관리 선택과 무관하다 — 커널은 동기 순수 함수, 어댑터는 비동기 읽기 API라, 상태관리를 무엇으로 하든 전부 App 영역 안의 일이다.

**포기한 것과 대가** —

1. **커널이 플랫폼 편의를 못 쓴다.** 플랫폼 객체를 그대로 넘기면 없었을 매핑 코드가 어댑터에 늘 남는다
2. **검증기는 수십 줄이라도 유지할 코드다.** 그리고 import 검사는 우회가 이론상 가능하다 — 혼자 하는 프로젝트에서 실질 위협은 아니지만, 이 도구는 악의가 아니라 실수를 막는 장치라는 한계를 안다
3. **저장 경계를 다루지 않았다.** ⓑ 덕에 M1은 성립하지만, 기록이 생기는 M2에서 저장 경계를 새로 정해야 한다. 미룬 것이지 공짜가 아니다 — 다만 이 프로젝트는 결정을 근거가 생기는 시점으로 옮기는 것을 방식으로 삼는다
4. **이미지 내용 기반 신호의 채택 비용이 올라갔다.** 결정 6 때문에 추출 과정까지 계약이 되므로, 알고리즘 선택지가 그만큼 좁아진다
5. **관행(3계층·Tuist)과 다른 구조는 설명 비용이 있다.** 이 문서가 그 비용의 지불이다
