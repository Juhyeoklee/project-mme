# 0003 — 에이전트 워크플로우

> 상태: **확정** · 2026-08-03
> `WHY.md` §3 전제 표 「에이전트 개발 워크플로우」 행의 ADR 칸이 이 문서를 가리킨다.

## 맥락

이 프로젝트의 코드 대부분은 에이전트가 생산한다. `WHY.md` §1은 그래서 둘째 증명을 *"에이전트의 생산 속도가 올라갈수록 아키텍처 경계가 유일한 품질 게이트가 된다는 문제의식과, 그걸 실제로 강제하는 장치"* 로 적었다. `0001`이 검증기와 CI를 세웠지만 빨간불이 뜨는 유일한 자리는 CI였다 — 사람이 커밋하고 push한 뒤다. 게이트가 코드 생산자(에이전트)의 루프 밖에 있었고, 위반은 생산 시점이 아니라 커밋 뒤에 발견된다.

시점: 검증기가 스캐폴딩(2026-08-03)에서 막 생겼고 화면 코드는 아직 없다. 더 일찍이면 물릴 대상이 없었고, 더 늦으면 게이트 없이 코드가 쌓인 뒤다.

## 결정

**1. 게이트는 세 층이다. 층마다 막는 주체와 시점이 다르다.**

| 층 | 무엇을 막는가 | 언제 |
|---|---|---|
| **컴파일러** | 패키지 간 의존 화살표 (`0001` 결정 4) | 빌드 즉시 |
| **검증기** | 컴파일러가 못 막는 3항목 (`0001` 결정 4) | **수정 직후(훅 — 이 문서)** + CI |
| **사람** | 의미 층 — 원칙 `P1`~`P5`의 해석 · 기획과 ADR 문서의 개정 · 세션 범위 · 커밋과 push | 세션 경계 |

에이전트가 넘을 수 없는 경계는 위 두 기계 층이다. 사람 층은 기계로 내려가지 않는다 — 내려갈 수 없어서가 아니라, 의미를 규칙 문장으로 흉내내는 것은 `0001` 근거 4가 SwiftLint를 자른 이유와 같은 이유로 배보다 배꼽이기 때문이다. 사람 층의 장치는 세션 체계다(결정 4).

**2. 검증기를 에이전트 루프 안으로 — 수정 직후 · 알림 · 우회 없음.**

에이전트가 `apple/` 안의 Swift 파일을 수정한 직후(Claude Code PostToolUse 훅) 검증기가 돌고, 위반이면 그 내용이 에이전트에게 되돌아간다(exit 2 → stderr). 검사 항목은 3항목 그대로다 — 훅은 항목을 늘리지 않고 **시점만 옮긴다**(`0001` 결정 4 유지).

- **차단이 아니라 알림이다.** 수정은 이미 일어났고, 에이전트가 위반 내용을 보고 그 자리에서 고친다. 최종 차단은 컴파일러와 CI가 맡는다
- **우회 변수는 없다.** 오탐의 처리 경로는 검증기가 이미 정의한다 — 금지 명단을 그 자리에서 고치고, diff에 남는다
- 훅 스크립트는 저장소에 산다: `apple/scripts/verify-boundaries-hook.sh`. 배선은 세션 루트(저장소 밖)의 `.claude/settings.json`이고, 내용은 이것이 전부다:

```json
{ "hooks": { "PostToolUse": [ { "matcher": "Edit|MultiEdit|Write",
  "hooks": [ { "type": "command",
    "command": "\"$CLAUDE_PROJECT_DIR\"/repo/apple/scripts/verify-boundaries-hook.sh" } ] } ] } }
```

**3. 빌드·테스트 루프에는 도구를 더하지 않는다.** 에이전트가 CI와 같은 명령(`swift test` · `xcodebuild` · 검증기)을 직접 돌리고 결과를 직접 읽는다. 루프는 이것으로 이미 닫혀 있다 — 스캐폴딩 세션이 실제로 이 방식으로 굴렀다.

**Xcode MCP는 실측으로 확인했고, 채택은 화면이 생기는 시점에 재판정한다.** Xcode 26.6의 `xcrun mcpbridge`가 MCP 도구 21개를 노출한다(`BuildProject` · `RunAllTests` · `GetBuildLog` · `RenderPreview` 등). 동작 조건: **Xcode가 해당 프로젝트를 열고 있어야 한다** — 아니면 initialize 뒤 무응답으로 매달린다(에러 없음, 2026-08-03 실측). 재판정 시점이 "화면"인 이유: 셸 대비 고유 가치가 `RenderPreview`(SwiftUI 화면 실물 확인)뿐이고, 화면이 없는 지금 그 값은 0이다.

**4. 세션 체계 — 이미 굴러가는 것을 결정으로 승격한다.** 닷새(2026-07-30 ~ 08-03) 동안 작업 세션 일곱 번이 이 형태로 돌았다(산출물 확정일 기준: 화면설계 · 디자인 토큰 · 실험 · 기획 · 모듈 경계 · 스캐폴딩 · 이 세션).

| | 푼 문제 | 포기한 것 |
|---|---|---|
| **플래닝/작업 세션 분리** — 플래닝이 범위를 정해 인계문을 쓰고, 작업 세션은 그것만 받는다 | 에이전트 세션은 매번 백지에서 시작한다 — 그 컨텍스트를 사람이 즉석에서 재구성하는 비용과 누락 | 세션 하나로 끝날 일도 두 세션을 거친다 |
| **인계문은 자체 완결이고, 읽으면 지운다** | 문서 간 참조가 얽혀 낡은 정보가 살아남는 것 | 상시 문서와 겹치는 내용이 인계문마다 다시 쓰인다 |
| **상태를 말하는 문서는 하나** (`CLAUDE.md`) | 상태 사본이 늘 때마다 반드시 생기는 갱신 누락 | 상태 이력이 문서에 안 남는다 — git이 대신한다 |

사람 층(결정 1)의 강제가 여기 있다: 인계문의 「제약」과 「하지 않을 것」이 세션마다 사람의 게이트를 문장으로 놓고, 커밋과 push를 사람이 잡는다.

## 근거

**1. 훅 지점 — 수정 직후가 유일하게 루프 안이다.** 턴 종료 시점이면 위반 위에 코드가 더 쌓인 뒤고, 커밋 직전이면 커밋을 사람이 하므로 애초에 에이전트 루프 밖이다. 비용은 실측 ~1초이고, `apple/` 안의 Swift 파일을 만졌을 때만 돈다 — 문서 편집에는 침묵한다.

**2. 알림이 차단보다 맞다.** PostToolUse는 구조적으로 차단이 불가능하고(수정이 먼저다), 차단이 필요하지도 않다 — 검증기의 오탐 정책이 *"오탐은 빨간불이 보여 그 자리에서 명단을 고치면 된다"* 로 이미 기울어 있고, 알림 방식이면 거짓 빨간불이 나도 세션이 멈추지 않는다. 우회 변수가 없어도 되는 이유가 이것이다: 우회가 필요한 상황(거짓 빨간불로 막힘)이 알림 방식에는 생기지 않는다.

**3. 도구 추가 0.** 훅 스크립트는 셸 내장과 grep/cut만 쓴다 — 경로 추출 하나를 위해 jq를 들이는 것도 `0001` 근거 4의 잣대를 통과하지 못한다. MCP 유보도 같은 잣대다: `0001` 결정 1은 *"구조적 사실이 기계 강제를 요구하는 곳에서만"* 을 요구하고, 있으면 좋은 것은 근거가 아니다.

**4. 세션 체계의 근거 강도는 닷새다.** 일곱 세션에서 실제로 반복된 것만 표에 남겼고, 검증됐다고 주장하지 않는다. 이 체계가 이 문서에 묶이는 이유는 하나다 — 훅과 CI가 막는 것은 코드의 경계뿐이고, 문서·기획·원칙의 경계는 세션 문장으로만 강제된다. 결정 1의 셋째 층이 비면 이 문서의 답이 두 층짜리가 된다.

## 결과와 대가

**얻는 것** — 경계 위반의 발견 시점이 커밋 뒤에서 생산 순간으로 이동한다. 사람이 CI 빨간불을 에이전트에게 옮겨 적는 경로가 사라진다. `WHY.md` §1 둘째 기둥의 "장치"가 주장이 아니라 저장소의 파일이 된다 — 훅 스크립트와 이 문서.

**포기한 것과 대가** —

1. **배선이 저장소 밖에 있다.** 클론만으로는 훅이 걸리지 않는다 — 워크스페이스(비공개)와 저장소(공개)를 가른 구조의 대가다. 위 인용이 보완이고, 저장소 안의 증거는 스크립트와 이 문서다
2. **훅은 에이전트의 파일 도구 경로만 본다.** 셸 명령으로 파일을 고치면 걸리지 않는다. CI가 받는다 — 훅은 게이트의 추가 시점이지 대체가 아니다
3. **수정마다 ~1초.** 검증기는 전체 스캔이라 코드베이스가 커지면 다시 잰다
4. **Xcode MCP를 미룬 대가로 화면 실물 확인은 사람 눈에 남는다** — 화면이 생겨 재판정할 때까지
5. **세션 체계는 닷새짜리 근거다.** `M1` 구현이 이 표를 깨면 해당 절만 새 ADR로 대체된다
