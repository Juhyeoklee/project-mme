# 0008 — Apple에서 UI 대부분을 WebView로 만들지 않는다

> 상태: **확정** · 결정 2026-07 (`WHY.md` 작성기) · 기록 2026-08-05
> `WHY.md` §5 탈락 표의 ADR 기록이다 — 새 논증이 아니라 §4·§5에 이미 적힌 것을 옮겨 닫는다.

## 맥락

Windows·Android가 웹 자산을 최대로 재사용한다면(§4), 같은 논리를 Apple에도 밀 수
있다 — 어차피 존재할 웹 화면을 WebView에 담으면 Apple 쪽 개발 비용도 준다.

## 결정

**Apple에서는 웹에 이미 존재해야 하는 화면만 재사용한다.** UI 대부분은 SwiftUI
네이티브다. Windows·Android와 방향이 반대인 것은 §4의 원칙 그대로다 — 다른 것은
재사용 비중뿐이고, 그 비중은 플랫폼의 역할에서 나온다.

## 근거

**1. 브릿지 고정비용이 절감분을 먹는다.** 인증 공유 · 네비게이션 상태 동기화 ·
디자인 시스템 이중 관리. 아끼려고 담은 화면마다 이 고정비용이 붙는다.

**2. 포트폴리오의 자기모순이 된다.** 화면 절반이 WebView면 SwiftUI 역량의 증거가
아니라 반대로 읽힌다(§1). Apple은 이 포트폴리오의 주 무대다.

## 잃은 것과 재검토 조건

**잃은 것** — 웹 자산이 이미 덮는 화면을 Apple에서 한 번 더 만든다. §4가 이 중복을
플랫폼 전략의 비용으로 받아들였다.

**재검토 조건** — 없다. 목표 포지션(iOS 네이티브)이 전제이고, 그것이 이 프로젝트의
존재 이유라 사실상 뒤집히지 않는다.
